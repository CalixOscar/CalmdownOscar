# Focused correct-score paper trial

User authorized building the free paper trial and proposed publishing at calmdownoscar.com/lastminute. Existing website is a static Vercel project in ../CalmdownOscar; no server credentials or API-Football key are verified. Follow its static-first approach. This plan precedes new API/data-model work.

Implement standalone HTML/CSS/JS PWA under trial/lastminute, with relative URLs and a worker scoped to /lastminute/. Use localStorage per browser for 1,000 virtual units, proposals, pending/open/settled entries, corrections and wallet version. No cloud wallet/account and no real-money execution.

Provide explicitly labelled deterministic replay (Norway–Denmark fictional example) for full end-to-end testing without a key. Keep replay and live wallets separate. Live mode fetches same-origin /api/lastminute-feed; server reads API_FOOTBALL_KEY and LASTMINUTE_FIXTURE_ID. Allow only that single configured fixture, no caller-supplied upstream paths or credentials. Return sanitized score/event state, never raw provider errors or secret headers. All GET data is intentionally public; there are no server mutation endpoints. Cache read-only data briefly to share the 100-request/day provider budget across friends; show remaining quota and stop when the provider refuses service. No claim that this is a calibrated profitable strategy or a guaranteed fresh scout feed.

Pilot signal: regulation second half at/after configured minute, fresh observed state, current score matches chosen correct-score outcome, known available incident state and stable score. Practice price and probability explicitly user entered; EV uses commission assumption. Optional auto-proposal waits for approval by default. Revalidate score/version on confirmation and after delay; require an observation newer than placement before simulated acceptance. Paper only: liquidity is not modelled and practice odds are not market quotes.

Settlement uses fulltime regulation score; never extra-time or penalty totals. Missing/abandoned result stays unresolved or void per explicit cancellation; score corrections reconcile balance. Persist updates and protect against repeated/double submissions. Pause on stale/offline data and never queue offline bets. Live feed timestamps represent retrieval, not independently verified provider latency.

Verification: node tests for strategy, delay, mutation/expiry, score changes, drawdown, outcome correction and live/replay separation; server handler tests for key absence, upstream errors, normalization and missing result; static/PWA paths and existing tests. Build/copy only trial files to website project, with scoped config integration and git diff. Verify deployment authorization/auth via standard Vercel CLI. If account access or key absent, preserve concrete deployable result and report blocked live setup instead of claiming publication.

Working with AI

Every AI session starts with the context it needs.

Unli Rice

Mac

Gives your AI tools the same starting point every session — who you are, what you’re building and for whom, and the rules to follow — and a To Do list that shows where the work actually stands.

  • Free
  • Open source

How it’s built

01 · What carries over

Identity, intent and guardrails

A profile records who is building, what for and for whom; house rules set the conventions a connected assistant reads at the start of a session. Claude, ChatGPT/Codex, Cursor and others reach the same notes over the Model Context Protocol (MCP), so a new session doesn’t start cold.

02 · Where the work stands

A To Do list worked out from the work itself

The list is built from the project folders you grant — work saved only on this Mac, branches not yet merged — plus each project’s written next step and the follow-ups an AI assistant filed. Repository status comes from the refs a repository already knows about; it doesn’t fetch or count commits. A widget keeps the AI-filed follow-ups in view.

03 · What it won’t do

Propose, never apply

Notes are append-only and suspected conflicts are flagged for a person to review. Unli Rice never edits another tool’s configuration: it hands you a block to paste. Shared instructions guide agents; they can’t force them to follow.

How it’s built

01 · Ordering

Codec-aware size, not pixel count

Biggest-first is only useful if the sizes are right, and a flat pixels-to-bytes coefficient is wrong in opposite directions: it over-counts a HEIC still by about 2.7× and under-counts a slo-mo clip by about 5.5×. The estimator reads dimensions, duration and codec from each asset’s metadata, so a 40,000-item library sorts without opening a single file. Every figure carries a ~ because it is an estimate.

02 · Safety

Non-destructive by design

Pick a period, heart the keepers, and one button clears everything else in that period. Without a period filter that button can queue 30,000+ photos, so every deletion goes through iOS’s own Recently Deleted instead of a hard delete — up to 30 days to undo a mistake.

03 · Version 1.3

Grid and photo side by side

On iPad, or an iPhone held sideways, a tapped photo opens beside the grid so your place never moves, and photos stored in iCloud open sharp straight away. Own Unli Disk? ClearSpace Pro is included; email me for your code.

How it’s built

01 · What it finds

Not just folder sizes

A tool that only shows what’s big can’t tell a build cache from an uncommitted repository. Unli Disk looks specifically for orphaned Git repositories and developer caches that generic visualisers show as “large folders”.

02 · Safety rule

Trash only, never unlink

Automated cleaners are a real data-loss risk on a machine full of unfinished work, so every deletion goes through the macOS Trash — recoverable, never a direct delete. That constraint was chosen on purpose.

03 · Detection method

Signal, not a model

The duplicate and blur pass isn’t a model call: a 64-bit perceptual hash finds candidate pairs, Apple’s Vision feature-print distance confirms the match, and a Laplacian score catches soft shots. An earlier version added an on-device vision-language model on top; it made scans slower for little gain, so it was cut. This pass is Mac-only — ClearSpace on iPhone does not claim it.

04 · Shared engine

One package, two platforms

The photo code lives in Packages/UnliDiskPhotos, the same engine ClearSpace uses. Unli Disk ($14.99 once) includes ClearSpace Pro for iPhone and iPad, sent as a one-time App Store code on request while the automatic unlock is tested.

How it’s built

01 · Grounding & state

Grounded, not generative

Venue and vendor picks come from Apple MapKit and Google Places, so the assistant reasons over real search results instead of inventing addresses. The model and the interface share one state model by design, so the assistant’s understanding can’t drift from what’s on screen.

02 · Relay architecture

No key in the app

Cloud calls go through a stateless relay on Vercel that holds the API key and enforces rate limits on the server, so nothing in the app can leak a credential. An earlier build ran models on the device (Llama 3.2 3B, then Qwen 2.5 3B); that path was pulled, and the app now runs a single cloud preset (Gemini Flash) with no on-device fallback.

03 · Data

Local-first, minimal data

SwiftData and CloudKit keep plans in sync across iPhone, iPad and Mac without a separate backend database. No user tracking; sensitive profile data stays on the device. Live since August 7, 2026.

How it’s built

01 · The problem

Nobody agrees on the score

Serve passes on every rally won, the server’s box flips with their own score, and doubles adds a rotation on top. A few rallies in, nobody is sure who serves, from which box, or when to change ends — so play stops while four people rebuild the score from memory.

02 · Keeping the rules

Serve, box, ends and score

Tracks server, receiver and diagonal box across singles and doubles, prompts the 11-point interval and change of ends, and handles BWF Law 14 lets. VAR Review opens the last rally from rolling memory at ¼× speed with frame stepping, so the players make the call themselves.

03 · Rig & desk

1 to 3 phones, a whole club event

Two net-post cameras and an optional umpire-chair camera give up to three synchronised replay angles, peer to peer with no Wi-Fi router. Court umpires scan a QR code to stream live scores to a central iPad that computes BWF tie-break standings, across up to 7 devices.

How it’s built

01 · The 0-0-2 puzzle

Resolving the three-number call

Only one partner serves at the start of a doubles match (0-0-2). After each side-out both players serve in turn, swapping boxes when they win points. Kitchen Vision tracks the serve number and positions and shows the call on screen for every point.

02 · One-thumb scoring & VAR

¼× replay on disputed calls

Built for one-thumb scoring during play. When a kitchen-line fault or close sideline call is disputed, VAR Review replays the rally at ¼× speed from rolling memory, frame by frame.

03 · Rig & master desk

Multi-camera sync and live standings

Two or three iPhones along the net posts sync over an offline peer-to-peer mesh for multi-angle review. Organisers can run multi-court round robins and brackets with QR-connected court scoring.

How it’s built

01 · Source of truth

Markdown in, graph out

Every tradition is a Markdown file with validated frontmatter. A build script resolves the links, computes backlinks and deterministically regenerates one graph.json, so a correction is a pull request against a text file rather than a write to a database nobody else can see.

02 · Sourcing rule

A claim is derived from a source, or removed

Origin pins are two separate steps: an editorial decision about where a tradition came from, then a lookup of that place against Wikidata that records the entity ID. The corpus needed that rule because it didn’t start with it — a generated first pass had pinned 127 traditions to one point near Jerusalem, including the Quakers, who began in 1650s Lancashire. Remediation resolved 619 distinct places.

Images failed the same way: captions had been written alongside an image search rather than from the file it returned, so an A∴A∴ journal was illustrated with a cruise ship. Every caption is now read off the Wikimedia Commons record for the file used, and 248 images that couldn’t be tied to their tradition were deleted rather than re-captioned.

03 · Running it

Nothing to trust

A static bundle: no backend, no analytics, no accounts, and no AI service involved when you read it. Filters mark how well attested a claim is instead of flattening scholarship and folklore into one confident voice.
